# 物联网环境监测系统 - 部署文档

## 一、环境要求

### 后端环境
- Python 3.10+
- MySQL 8.0+
- Redis 6.0+
- MQTT Broker (Mosquitto/EMQX)

### 前端环境
- Node.js 16+
- npm 8+

## 三、后端部署

### 3.1 本地开发部署

#### 1. 安装依赖
```bash
cd backend
pip install -r requirements.txt
```

#### 2. 配置数据库

确保MySQL服务已启动，并创建数据库：

```sql
CREATE DATABASE wlw CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

#### 3. 配置环境变量

复制 `.env.example` 为 `.env` 并修改配置：

```bash
cp .env .env
```

编辑 `.env` 文件：

```env
# Django配置
DJANGO_DEBUG=True
DJANGO_SECRET_KEY=your-secret-key-here
ALLOWED_HOSTS=localhost,127.0.0.1

# 数据库配置
DB_HOST=39.105.122.26
DB_PORT=3306
DB_NAME=wlw
DB_USER=root
DB_PASSWORD=Lxr123123

# Redis配置
REDIS_URL=redis://localhost:6379/1

# MQTT配置
MQTT_HOST=localhost
MQTT_PORT=1883
```

#### 4. 数据库迁移

```bash
python manage.py makemigrations
python manage.py migrate
```

#### 5. 创建超级用户

```bash
python manage.py createsuperuser
```

#### 6. 启动服务

```bash
# 启动Django开发服务器
python manage.py runserver

# 启动MQTT服务（新开终端）
python manage.py start_mqtt

# 启动Celery Worker（新开终端，可选）
celery -A iot_system worker -l info
```

#### 7. 访问API文档

浏览器访问：`http://localhost:8000/swagger/`

### 3.2 Docker部署

#### 1. 构建镜像

```bash
cd backend
docker-compose build
```

#### 2. 配置环境变量

创建 `.env` 文件（如上所示）

#### 3. 启动所有服务

```bash
docker-compose up -d
```

#### 4. 查看日志

```bash
# 查看所有服务日志
docker-compose logs -f

# 查看特定服务日志
docker-compose logs -f backend
docker-compose logs -f mqtt
```

#### 5. 停止服务

```bash
docker-compose down
```

### 3.3 生产环境部署

#### 1. 使用Gunicorn + Uvicorn

安装生产依赖：

```bash
pip install gunicorn uvicorn
```

启动服务：

```bash
gunicorn iot_system.asgi:application -k uvicorn.workers.UvicornWorker -b 0.0.0.0:8000 --workers 4
```

#### 2. 使用Nginx反向代理

Nginx配置示例：

```nginx
upstream iot_backend {
    server 127.0.0.1:8000;
}

upstream iot_websocket {
    server 127.0.0.1:8001;
}

server {
    listen 80;
    server_name your-domain.com;

    # HTTP重定向到HTTPS
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    # API代理
    location /api/ {
        proxy_pass http://iot_backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # WebSocket代理
    location /ws/ {
        proxy_pass http://iot_websocket;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
    }

    # 前端静态文件
    location / {
        root /path/to/frontend/dist;
        try_files $uri $uri/ /index.html;
    }
}
```


## 七、常见问题

### 7.1 数据库连接失败

**问题**：`django.db.utils.OperationalError: unable to open database file`

**解决**：
1. 检查数据库服务是否启动
2. 检查 `.env` 文件中的数据库配置是否正确
3. 确保数据库用户有访问权限

### 7.2 MQTT连接失败

**问题**：MQTT客户端无法连接到Broker

**解决**：
1. 检查MQTT Broker是否启动
2. 检查防火墙是否允许MQTT端口（默认1883）
3. 检查MQTT用户名和密码配置

### 7.3 WebSocket连接失败

**问题**：前端WebSocket无法建立连接

**解决**：
1. 检查后端WebSocket服务是否启动
2. 检查Nginx配置是否正确代理WebSocket
3. 检查WSS证书配置（HTTPS环境）

### 7.4 前端API请求404

**问题**：前端请求API返回404

**解决**：
1. 检查 `vite.config.js` 中的代理配置
2. 检查后端URL路由配置
3. 确保API路径前缀正确（`/api/v1/`）

### 7.5 CORS错误

**问题**：浏览器控制台显示CORS错误

**解决**：
1. 在 `settings.py` 中配置 `CORS_ALLOWED_ORIGINS`
2. 或者在开发环境设置 `CORS_ALLOW_ALL_ORIGINS = True`

## 十一、备份与恢复

### 11.1 数据库备份

```bash
# 备份
mysqldump -u root -p wlw > backup_$(date +%Y%m%d).sql

# 恢复
mysql -u root -p wlw < backup_20240120.sql
```

### 11.2 媒体文件备份

```bash
# 备份媒体文件
tar -czf media_$(date +%Y%m%d).tar.gz backend/media/
```

### 11.3 自动备份脚本

创建 `backup.sh`：

```bash
#!/bin/bash
BACKUP_DIR="/var/backups/iot"
DATE=$(date +%Y%m%d_%H%M%S)

# 创建备份目录
mkdir -p $BACKUP_DIR

# 备份数据库
mysqldump -u root -pLxr123123 wlw > $BACKUP_DIR/db_$DATE.sql

# 备份媒体文件
tar -czf $BACKUP_DIR/media_$DATE.tar.gz backend/media/

# 删除7天前的备份
find $BACKUP_DIR -name "*.sql" -mtime +7 -delete
find $BACKUP_DIR -name "*.tar.gz" -mtime +7 -delete
```

添加到crontab：

```bash
# 每天凌晨2点备份
0 2 * * * /path/to/backup.sh
```
