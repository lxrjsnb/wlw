## 三、核心业务流程

### 3.1 设备注册与数据上报流程

```
[设备] ──[MQTT Connect]──> [MQTT Broker]
                                    │
                                    ├─[Subscribe]─> [Django MQTT服务]
                                    │                    │
                                    │                    ▼
                                    │              [数据校验]
                                    │                    │
                                    │                    ▼
                                    │              [存储到MySQL]
                                    │                    │
                                    │                    ▼
                                    │              [检查告警规则]───> [触发告警] ──> [WebSocket推送]
                                    │
[前端] ──[WebSocket连接]──> [Django Channels] ──[推送实时数据]──> [前端更新界面]
```

### 3.2 用户认证与API调用流程

```
[前端] ──[登录请求]──> [Django Auth API] ──[验证]──> [返回JWT Token]
        │                                        │
        │                                        ▼
        │                                 [存储Token到本地]
        │                                        │
        │                                        ▼
        │                                 [后续API请求带Token]
        │                                        │
        ▼                                        ▼
[前端界面] ──[请求设备数据]──> [Django API] ──[JWT验证]──> [查询数据]──> [返回结果]
```

### 3.3 告警处理流程

```
[MQTT接收数据] ──[解析]──> [获取当前值]
                           │
                           ▼
                  [查询告警规则]
                           │
                           ▼
                  [判断是否超阈值] ──[否]──> [结束]
                           │
                          [是]
                           │
                           ▼
                    [创建告警记录]
                           │
                           ▼
                    [WebSocket推送]
                           │
                           ▼
                    [前端弹窗通知]
                           │
                           ▼
                   [管理员处理告警]
```

## 五、核心API接口设计

### 5.1 认证接口
- `POST /api/auth/login/` - 用户登录
- `POST /api/auth/logout/` - 用户登出
- `POST /api/auth/refresh/` - 刷新Token
- `GET /api/auth/user/` - 获取当前用户信息

### 5.2 设备管理接口
- `GET /api/devices/` - 获取设备列表
- `POST /api/devices/` - 创建设备
- `GET /api/devices/{id}/` - 获取设备详情
- `PUT /api/devices/{id}/` - 更新设备
- `DELETE /api/devices/{id}/` - 删除设备
- `POST /api/devices/{id}/control/` - 远程控制设备

### 5.3 传感器数据接口
- `GET /api/sensors/data/` - 获取监测数据（支持筛选、分页）
- `GET /api/sensors/latest/{device_id}/` - 获取设备最新数据
- `GET /api/sensors/statistics/{device_id}/` - 获取数据统计
- `POST /api/sensors/import/` - 批量导入数据
- `GET /api/sensors/export/` - 导出数据

### 5.4 告警接口
- `GET /api/alarms/` - 获取告警列表
- `GET /api/alarms/{id}/` - 获取告警详情
- `PUT /api/alarms/{id}/resolve/` - 处理告警
- `GET /api/alarm-rules/` - 获取告警规则
- `POST /api/alarm-rules/` - 创建告警规则
- `PUT /api/alarm-rules/{id}/` - 更新告警规则
- `DELETE /api/alarm-rules/{id}/` - 删除告警规则

### 5.5 WebSocket接口
- `ws://host/ws/realtime/` - 实时数据推送
- `ws://host/ws/alarms/` - 告警推送


## 七、数据流设计

### 7.1 实时数据流
1. MQTT订阅设备数据 → 接收数据 → 存储到MySQL
2. Django Channels建立WebSocket连接 → 轮询/触发推送 → 前端实时更新
3. 告警检测 → 触发告警记录 → WebSocket推送告警通知

### 7.2 历史数据查询流
1. 前端请求 → API接口 → 参数校验 → 查询MySQL → 返回分页数据
2. 支持按时间范围、设备、传感器类型筛选
3. 支持导出为CSV/Excel

## 八、安全性设计

1. **认证安全**：JWT Token + Token过期机制
2. **数据传输**：HTTPS + WSS
3. **MQTT安全**：用户名/密码认证
4. **数据校验**：前后端双重校验
5. **权限控制**：基于角色的访问控制（RBAC）
6. **SQL注入防护**：使用ORM参数化查询

## 九、扩展性设计

1. **新增传感器类型**：只需在SensorType表中添加配置，无需修改代码
2. **新增设备**：通过设备注册接口，自动分配ID和规则
3. **告警规则**：支持动态配置，支持多条件组合
4. **数据存储**：支持分区表和索引优化，应对海量数据
5. **微服务化**：各模块独立，可拆分为独立服务
